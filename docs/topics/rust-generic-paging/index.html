Rustジェネリック構造体の解説

型パラメータと定数ジェネリクスの活用

🔧 ジェネリック構造体とは

ジェネリック構造体は、型をパラメータとして受け取る構造体です。同じ構造でも異なる型で使い回せるため、コードの再利用性と型安全性を両立できます。

基本的な例

// 基本的なジェネリック構造体
struct Container<T> {
    value: T,
}

// 使用例
let int_container = Container { value: 42i32 };
let string_container = Container { value: "Hello".to_string() };

🔢 定数ジェネリクス（Const Generics）

WasabiOSの実装では、定数ジェネリクスを活用しています。これは型だけでなく、定数値もパラメータとして受け取る機能です。

WasabiOSでの使用例

pub struct Entry<const LEVEL: usize, const SHIFT: usize, NEXT> {
    value: u64,
    next_type: PhantomData<NEXT>,
}

🎯 パラメータの説明

  • const LEVEL: usize: ページテーブルのレベル（1-4）
  • const SHIFT: usize: アドレス計算用のビットシフト値
  • NEXT: 次のレベルの型（型パラメータ）

👻 PhantomDataの役割

PhantomDataは「幽霊データ」で、実際にはメモリを消費しないが型システムに型情報を伝える仕組みです。

use core::marker::PhantomData;

// PhantomDataがない場合、NEXTが使われていないとコンパイラが警告
// PhantomDataがあることで、NEXTが型システムで使用されていることを示す
next_type: PhantomData<NEXT>,

💡 PhantomDataの利点

  • メモリサイズ: 0バイト（実行時オーバーヘッドなし）
  • 目的: 型システムにNEXTが使用されていることを示す
  • 効果: NEXTが「未使用」警告を出さない

🔧 implブロックでの型パラメータ再宣言

ジェネリック構造体にメソッドを実装する際は、implブロックで型パラメータを再宣言する必要があります。

// 構造体の定義
pub struct Entry<const LEVEL: usize, const SHIFT: usize, NEXT> {
    value: u64,
    next_type: PhantomData<NEXT>,
}

// implブロックでの再宣言
impl<const LEVEL: usize, const SHIFT: usize, NEXT> Entry<LEVEL, SHIFT, NEXT> {
    fn read_value(&self) -> u64 {
        self.value
    }
    
    fn table(&self) -> Result<&NEXT> {
        // NEXTを戻り値の型として使用
        if self.is_present() {
            Ok(unsafe { &*((self.value & !ATTR_MASK) as *const NEXT ) })
        } else {
            Err("Page Not Found")
        }
    }
}

🤔 なぜ再宣言が必要？

  • implブロックは独立したスコープ
  • 構造体で宣言したパラメータをimpl内で使うには再宣言が必要
  • 「どんな型パラメータの時に」という条件を明示

🔄 型の具体化プロセス

コンパイル時に、ジェネリック構造体は具体的な型に展開されます。

型エイリアス定義

pub type PT = Table<1, 12, [u8; PAGE_SIZE]>;

Entry構造体とTable構造体の設計

🏗️ Entry構造体の設計

各ページテーブルエントリを表現する構造体です。

Entry構造体の完全な実装

#[repr(transparent)]
pub struct Entry<const LEVEL: usize, const SHIFT: usize, NEXT> {
    value: u64,
    next_type: PhantomData<NEXT>,
}

impl<const LEVEL: usize, const SHIFT: usize, NEXT> Entry<LEVEL, SHIFT, NEXT> {
    fn read_value(&self) -> u64 {
        self.value
    }
    
    fn is_present(&self) -> bool {
        (self.read_value() & (1 << 0)) != 0
    }
    
    fn is_writable(&self) -> bool {
        (self.read_value() & (1 << 1)) != 0
    }
    
    fn is_user(&self) -> bool {
        (self.read_value() & (1 << 2)) != 0
    }
    
    fn table(&self) -> Result<&NEXT> {
        if self.is_present() {
            Ok(unsafe { &*((self.value & !ATTR_MASK) as *const NEXT ) })
        } else {
            Err("Page Not Found")
        }
    }
}

🔍 重要な設計ポイント

  • #[repr(transparent)]: 構造体のメモリレイアウトを内部のu64と同じにする
  • PhantomData: 実行時オーバーヘッドなしで型情報を保持
  • フラグ解析メソッド: ページテーブルエントリの属性を型安全に取得
  • table()メソッド: 次のレベルへの型安全な参照を提供

🏛️ Table構造体の設計

512個のエントリを持つページテーブルを表現する構造体です。

Table構造体の完全な実装

#[repr(align(4096))]
pub struct Table<const LEVEL: usize, const SHIFT: usize, NEXT> {
    entry: [Entry<LEVEL, SHIFT, NEXT>; 512],
}

impl<const LEVEL: usize, const SHIFT: usize, NEXT: core::fmt::Debug> Table<LEVEL, SHIFT, NEXT> {
    fn format(&self, f: &mut fmt::Formatter) -> fmt::Result {
        writeln!(f, "L{}Table @ {:#p} {{", LEVEL, self)?;
        for i in 0..512 {
            let e = &self.entry[i];
            if !e.is_present() {
                continue;
            }
            writeln!(f, " entry[{:3}] = {:?}", i, e)?;
        }
        writeln!(f,"}}")
    }
    
    pub fn next_level(&self, index: usize) -> Option<&NEXT> {
        self.entry.get(index).and_then(|e| e.table().ok())
    }
}

🔍 重要な設計ポイント

  • #[repr(align(4096))]: 4KBページ境界にアライメント
  • 512エントリ: x86_64の標準的なページテーブルサイズ
  • トレイト制約: NEXT: Debugでデバッグ表示を可能に
  • フィルタリング: 存在するエントリのみを表示
  • 型安全なナビゲーション: next_level()で次のレベルへ安全にアクセス

🎨 デバッグ表示の実装

構造化されたデバッグ出力により、ページテーブルの内容を人間が読める形で表示します。

Debug traitの実装

impl<const LEVEL: usize, const SHIFT: usize, NEXT> fmt::Display for Entry<LEVEL, SHIFT, NEXT> {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        write!(
            f,
            "L{}Entry @ {:#p} {{ {:#018x} {}{}{}",
            LEVEL,
            self,
            self.read_value(),
            if self.is_present() { "P" } else { "N" },
            if self.is_writable() { "W" } else { "R" },
            if self.is_user() { "U" } else { "S" }
        )?;
        write!(f, "}}")
    }
}

🎯 デバッグ出力の特徴

  • レベル表示: L4Entry, L3Entryなどでレベルを明示
  • アドレス表示: エントリの物理アドレスを表示
  • 値の表示: 64bit値を16進数で表示
  • フラグの表示: P(Present), W(Writable), U(User), S(Supervisor)
  • 存在フィルタ: 存在するエントリのみを表示してノイズを削減

🎯 実行結果の解析

1. PML4テーブル（レベル4）
  • アドレス: 0xbfc01000 - CR3レジスタが指すアドレス
  • エントリ[0]: 0x00000000bfc02023 - 次のレベル（PDPT）を指す
  • フラグ: PWS = Present, Writable, Supervisor
  • 管理範囲: 仮想アドレス空間の最初の512GB
2. PDPTテーブル（レベル3）
  • アドレス: 0xbfc02000 - PML4[0]が指すアドレス
  • エントリ数: 64個のエントリが有効（0-63）
  • 管理範囲: 各エントリが1GBずつ、合計64GB分
  • 特徴: 連続的なメモリ領域がマップされている
3. PDテーブル（レベル2）
  • アドレス: 0xbfc03000 - PDPT[0]が指すアドレス
  • エントリ数: 512個すべてのエントリが有効
  • ページサイズ: 2MBページを直接マップ（大きなページ）
  • 物理アドレス: 0x0, 0x200000, 0x400000... と連続配置
4. 最終結果: None
  • 理由: PDレベルで2MBページとして直接マップされている
  • 意味: PTレベル（4KBページ）は存在しない
  • 効率性: 大きなページサイズでTLBミスを削減
