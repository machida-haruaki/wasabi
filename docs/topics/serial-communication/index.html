携帯電話の基地局が壊れても、無線通信なら確実に外部と連絡が取れる。

🎯 なぜこの技術が必要なのか

  • ブートストラップ問題の解決: 画面出力機能がない状態でのデバッグ
  • ハードウェア独立性: グラフィックカードに依存しない通信手段
  • 確実性の保証: 最小限の初期化で確実に動作
  • 外部システム連携: 開発マシンとの橋渡し役
  • リアルタイム監視: システムの動作状況を即座に把握

🔌 シリアルポートとは何か

シリアルポートは、データを1ビットずつ順番に送信する通信ハードウェアです。単なる設定やソフトウェアではなく、実際にデータの送受信を行う物理的なハードウェアです。

🏗️ ハードウェアの主要構成要素

  • 送信バッファ: 送信待ちのデータを一時保存
  • 受信バッファ: 受信したデータを一時保存
  • シフトレジスタ: データを1ビットずつ送受信
  • ボーレートジェネレータ: 正確なタイミング制御
  • 制御レジスタ: 通信設定を管理

⚡ シリアル通信の仕組み

シリアル通信では、文字を送信する際に特定の形式でデータを構成します。例として、文字'A'（バイナリ: 01000001）の送信過程を見てみましょう：

スタートビット: 通信開始の合図
データビット: 実際の文字データ（8ビット）
ストップビット: 通信終了の合図

📊 通信パラメータ

  • ボーレート: 115200bps（1秒間に115,200ビット送信）
  • データビット: 8ビット（1文字あたり）
  • パリティ: なし（エラー検出なし）
  • ストップビット: 1ビット
  • フロー制御: ハードウェアフロー制御

送信時間の計算：

1文字 = スタートビット(1) + データビット(8) + ストップビット(1) = 10ビット 115200bps ÷ 10ビット = 11,520文字/秒 1文字あたりの送信時間 = 1 ÷ 11,520 ≈ 87マイクロ秒

🎯 OS開発におけるシリアルポートの重要性

OS開発では「鶏と卵」問題が発生します。シリアルポートはこの問題を解決する「最後の砦」として機能します：

🐔 鶏と卵問題

OSを作っている → まだ画面出力機能がない → デバッグできない → OSが作れない

🛡️ シリアルポートが解決する理由

🔧 ハードウェアレベルでの独立性

  • CPUと直接接続された非常にシンプルなハードウェア
  • グラフィックカード、メモリ管理、ファイルシステムと完全に独立
  • 複雑なドライバが不要

⚡ 最小限の初期化で動作

  • I/Oポートへの数回の書き込みのみで動作開始
  • メモリ割り当て不要、複雑な設定不要
  • CPU起動直後から使用可能

✅ 確実な出力保証

  • 同期通信による確実なデータ送信
  • バッファリングが最小限
  • 送信完了を確認してから次のデータを送信

📋 各レジスタの詳細

📤 データレジスタ (base + 0)

  • 送受信データの読み書き
  • DLAB=1時はボーレート下位バイト
  • 最も頻繁に使用されるレジスタ

🔔 割り込み有効レジスタ (base + 1)

  • 各種割り込みの有効/無効制御
  • DLAB=1時はボーレート上位バイト
  • 初期化時は通常0x00に設定

📦 FIFO制御レジスタ (base + 2)

  • FIFOバッファの有効化
  • 送受信バッファのクリア
  • 割り込み閾値の設定

⚙️ ライン制御レジスタ (base + 3)

  • データフォーマット設定
  • DLAB（Data Latch Access Bit）制御
  • パリティ、ストップビット設定

🔧 シリアルポート初期化プロセス

シリアルポートの初期化は、ハードウェアレジスタを正しい順序で設定することで行われます。各ステップには技術的な理由があります。

1 割り込み無効化
初期化中に予期しない割り込みを防ぐため、IER（Interrupt Enable Register）を0x00に設定
2 DLAB有効化
ボーレート設定レジスタにアクセスするため、LCR（Line Control Register）のDLABビットを1に設定
3 ボーレート設定
115200bps用の除数（0x0001）を上位・下位バイトに分けて設定
4 データフォーマット
8ビット、パリティなし、ストップビット1に設定し、DLABを無効化（LCR = 0x03）
5 FIFO制御
FIFOを有効化し、送受信バッファをクリア、14バイト閾値を設定（FCR = 0xC7）
6 モデム制御
DTR、RTS信号を有効化し、割り込みを有効にする（MCR = 0x0B）
// WasabiOSでの初期化実装 pub fn init(&mut self) { // ステップ1: 全ての割り込みを無効化
write_io_port_u8(self.base + 1, 0x00);
// ステップ2: DLABを有効にしてボーレート設定モードに
write_io_port_u8(self.base + 3, 0x80);
// ステップ3: ボーレート除数を設定（115200bps用） const BAUD_DIVISOR: u16 = 0x0001;
write_io_port_u8(self.base, (BAUD_DIVISOR & 0xff) as u8);
write_io_port_u8(self.base + 1, (BAUD_DIVISOR >> 8) as u8);
// ステップ4: データフォーマットを設定し、DLABを無効化
write_io_port_u8(self.base + 3, 0x03);
// ステップ5: FIFO制御を設定
write_io_port_u8(self.base + 2, 0xc7);
// ステップ6: モデム制御信号を設定
write_io_port_u8(self.base + 4, 0x0B);
}

📤 文字送信の実装

シリアル通信は同期通信です。送信バッファが空になるまで待機してから次の文字を送信する必要があります。

🔄 送信手順

1️⃣ 送信準備完了チェック

LSR（Line Status Register）のbit 5を監視して、送信ホールドレジスタが空かどうかを確認

2️⃣ ビジーウェイト

送信バッファが空になるまで待機。busy_loop_hint()でCPU最適化

3️⃣ データ送信

データレジスタ（base + 0）に文字を書き込んで送信開始

// 1文字送信の実装 pub fn send_char(&self, c: char) { // 送信準備完了まで待機 // LSR (Line Status Register) = base + 5 // bit 5 = THRE (Transmitter Holding Register Empty) // 0x20 = 0010 0000 (bit 5のマスク)
while (read_io_port_u8(self.base + 5) & 0x20) == 0 {
// CPUに最適化ヒントを提供（PAUSE命令）
busy_loop_hint();
} // データレジスタ（base + 0）に文字を書き込み
write_io_port_u8(self.base, c as u8)
}

📝 文字列送信の実装

// 文字列送信の実装 pub fn send_str(&self, s: &str) { let mut sc = s.chars(); let slen = s.chars().count(); // 各文字を順次送信
for _ in 0..slen {
self.send_char(sc.next().unwrap());
} }

🍃 WasabiOSでの実装

WasabiOSでは、シリアル通信機能を効率的で使いやすい形で実装しています。

🏗️ SerialPort構造体の設計

/// シリアルポート制御構造体 #[repr(C)] pub struct SerialPort { /// シリアルポートのベースI/Oアドレス /// COM1: 0x3F8, COM2: 0x2F8, COM3: 0x3E8, COM4: 0x2E8
base: u16,
} impl SerialPort { /// COM1ポート用のシリアルポートインスタンスを作成
pub fn new_for_com1() -> Self {
Self::new(0x3f8)
} }

✍️ fmt::Writeトレイトの実装

Rustの標準フォーマット機能との統合により、write!やwriteln!マクロが使用可能になります：

impl fmt::Write for SerialPort { fn write_str(&mut self, s: &str) -> fmt::Result {
let serial = Self::default();
serial.send_str(s);
Ok(()) } }

🎯 まとめ

シリアル通信は、OS開発における「最後の砦」として、確実で信頼性の高い通信手段を提供します。

✅ シリアル通信の利点

  • 確実性
    最小限の初期化で確実に動作
  • 独立性
    他のシステムに依存しない
  • シンプルさ
    理解しやすい仕組み
  • 汎用性
    様々な環境で利用可能
  • デバッグ効率
    リアルタイム監視が可能

⚠️ 注意点

  • 速度制限
    115200bpsの帯域制限
  • 文字制限
    非ASCII文字の表示問題
  • ブロッキング動作
    送信完了まで待機が必要
  • ハードウェア依存
    物理ポートの存在が前提
  • 設定の複雑さ
    レジスタ設定の理解が必要
